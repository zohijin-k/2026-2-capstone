# 현황 대시보드 (dashboard/)

전북청년 함께 두배적금 신청·심사·선정 현황 대시보드 프론트엔드 초안. 담당: 채운.
엔진·데모 사이트와 연동하지 않고 **목업 데이터**로 동작한다.

## 실행

```bash
cd dashboard
npm install
npm run dev      # http://localhost:5173
npm run build    # 타입체크 + 프로덕션 빌드 (dist/)
npm run lint
```

## 화면 구성

| 영역 | 내용 |
|---|---|
| 필터 바 | 기준일 슬라이더(3.3 접수 시작 ~ 5.15 발표, 재생 가능) · 시군 선택 |
| KPI | 접수 건수(정원 대비 접수율), 경쟁률, 심사 진행률, 적합률, 선정자, 평균 처리기간 |
| 시군별 현황 | 전북 14개 시군 지도 (신청자 수/경쟁률/심사 진행률/평균 처리기간 전환, 클릭 시 필터) |
| 접수 추이 | 일별·누적 접수(제출 완료) 건수 |
| 시군별 심사 진행 | 서류확인 대기 · 자격심사 중 · 적합 · 부적합 비율 |
| 부적합 사유 | 서류/자격/2차 검증 단계별 사유 상위 10개 |
| 연령 분포 / 신청자 특성 | 평균 연령, 연령대, 성별, 근로유형, 건강보험 가입유형, 가구원 수 |
| 시군별 상세 | 위 지표의 표 보기 |
| **담당자용** (구분선 아래) | 배점별 신청자 분포(선정권·커트라인 선), 시군별 선정 커트라인 표 |

배점·커트라인 정보는 담당자만 볼 수 있어야 한다. 현재 초안은 화면을 구분선으로 나눠 표시만 한 상태이며,
실서비스에서는 로그인·권한 확인 후 서버가 담당자에게만 이 영역의 데이터(`scoreBins`, `cutoff`)를 내려줘야 한다
(프론트에서 숨기는 것만으로는 데이터가 노출됨).

## 폴더 구조

```
src/
├── App.tsx                 # 레이아웃, 필터 상태(기준일·시군·테마)
├── data/
│   ├── generate.ts         # 결정론적 목업 데이터 생성 (시드 고정)
│   ├── regions.ts          # 시군별 정원·접수 규모('26년 기준)
│   ├── scoring.ts          # 심사표 배점·동점자 규칙
│   ├── lifecycle.ts        # 기준일 시점의 심사 단계·운영 단계 판정
│   ├── types.ts
│   └── jeonbuk.geo.json    # 전북 14개 시군 경계
├── lib/metrics.ts          # 기준일·시군 필터 → 화면 지표 스냅샷 계산
├── charts/                 # ECharts 등록, 공통 축/툴팁 스타일
├── components/             # 카드·차트 컴포넌트
└── theme.ts                # 차트 색상 토큰 (라이트/다크)
```

## 목업 데이터 기준

- 실제 자료 기반: 시군별 접수인원(총 12,821건)·정원(1,300명), 신청기간·발표일, 심사표 배점과 동점자 우선순위,
  1차 선정 120% → 2차 검증 절차, 공고문 '미비 서류 예시'
- 가정값: 연령·성별·근로유형 등 분포, 부적합 비율(서류 9%·자격 11%·2차 1.5%), 시군별 처리 속도
- **커트라인 예상**: 판정 완료 건의 적합률을 미판정 건에 적용해 고득점부터 정원을 채우는 최저 총점.
  2차 검증 이후에는 최종 선정자 최저점(확정값)

실데이터 연동 시 `lib/metrics.ts`의 `computeSnapshot`이 받는 `Dataset`(`data/types.ts`) 형태로 API 응답을 맞추면
화면 컴포넌트는 그대로 쓸 수 있다.
