# 전북 청년정책 신청서류 자동심사 시스템

전북특별자치도 청년정책(함께 두배적금·청년 취업지원패키지)의 서류 접수·심사를 자동화하는 프로젝트다.
두배적금은 정원 1,300명에 12,821건이 몰리면서 인당 7~8개 서류를 공무원이 전부 수기로 심사해야 했고
(전주시 기준 심사에 1~2개월 소요), 콜센터에는 자격요건·제출서류 관련 반복 문의가 쏟아졌다.
이 시스템은 서류 업로드 단계에서 문제를 즉시 알려 주고, 공고문 기준 자격 요건을 규칙으로 점검해
담당자의 수작업 부담과 신청자의 대기 시간을 함께 줄이는 것을 목표로 한다.

> **최종 버전은 항상 `main` 브랜치다.** 다른 브랜치는 받지 않아도 된다.

## 최종 버전 받기

처음 받는 경우:

```bash
git clone https://github.com/zohijin-k/2026-2-capstone.git
cd 2026-2-capstone
```

`git clone`은 기본으로 `main`을 받는다. 이미 받아 둔 경우에는 최신으로 갱신만 한다.

```bash
git checkout main
git pull
```

git을 쓰지 않는다면 GitHub 저장소 첫 화면에서 브랜치가 `main`인지 확인한 뒤 **Code → Download ZIP**으로 받는다.

받은 뒤 실행 방법은 아래 [빠른 시작](#빠른-시작)을 따른다.

## 함께 작업하는 규칙

1. 작업을 시작하기 전에 `main`을 최신으로 받는다: `git checkout main && git pull`
2. 새 브랜치를 만든다: `git checkout -b feat/<작업-내용>`
3. 커밋하고 push한 뒤, GitHub에서 `main`으로 가는 PR을 만든다.
4. PR에 무엇을 바꿨는지 적고 병합한다. 병합한 브랜치는 삭제한다.
5. `main`에 직접 push하지 않는다.
6. 커밋 전에 `git status`로 실제 서류, `.env`, API 키가 섞이지 않았는지 확인한다.

## 왜 필요한가

- 신청 13,000건 근처, 서류는 인당 7~8개 → 총 10만 건 가까운 서류를 수기 처리
- 콜센터 상담 3,073건 중 38%가 자격요건 문의, 14%가 제출서류 문의 — 신청자가 스스로 확인할 방법이 없어 반복됨
- '27년 운영계획은 담당자 중심 확인·안내에서 시스템 기반 자동 확인·분류·알림으로 전환하는 방향을 제시한다

## 현재 상태

- 사업 2종(두배적금·취업지원패키지)의 신청·서류 검토 흐름을 데모로 제공한다.
- 업로드 직후 서류 종류·발급일·필수 항목을 판정하고, 제출 시 공고문 기준 자격 요건을 확인한다.
- 다른 서류를 잘못 올리면 어떤 서류를 올린 것 같은지 한 줄로 알려 준다.
- 건강보험료 납부확인서·자격확인서는 건강보험 가입자(부모) 명의도 인정하고, 신청자 화면에는 타인 이름을 보여 주지 않는다.
- 가구원 수는 건강보험 자격확인서로만 판정한다.
- 담당자 심사 화면에서 판정 근거와 원본 서류를 함께 확인할 수 있다.
- 사업별 심사 기준을 버전으로 관리하며, 신청서는 생성 당시 기준 버전에 고정된다.
- 도청 제공 전북AI OCR 연결과 판독기(초본·납부확인서·자격득실)를 준비했다. 기관 확인 전까지 데모 판정에는 쓰지 않는다.

### 진행 중인 작업

- 신청 서식을 웹 입력 대신 원본 PDF 위에서 직접 작성 (미리보기·재작성 포함)
- 4대 사회보험 가입내역 확인서 판독기
- 두배적금 자격요건(거주·연령·근로·소득) 기준화와 담당자 행정 조회 체크리스트
- 근로 요건 판정, 공공기관·제외 업종 의심 표시

## 데모 둘러보기

1. **신청자 화면:** 본인인증 → 자가진단 → 신청서 작성 → 동의 → (취업패키지는 지원 항목 선택) → 서류 업로드 → 최종 확인 → 마이페이지
2. **담당자 화면:** 신청 목록 → 심사 상세(판정 근거, 원본 서류, 작성본)
3. **기준 설정(관리자):** 첫 화면에서 사업별 심사 기준을 바꾸고 버전 이력을 본다.

시연 대본은 [`demo/docs/demo-script.md`](demo/docs/demo-script.md)에 있다. 시연 전 데이터를 비우려면 저장소 루트에서 `python -m demo.backend.reset`을 실행한다.

## 빠른 시작

필요한 버전은 Python 3.12 이상과 Node.js 20 이상이다. macOS와 Linux에서 백엔드·프론트엔드는 실행할 수 있다. Apple Vision OCR은 macOS 전용이며 Linux에서는 사용할 수 있는 다른 OCR 엔진이 필요하다.

### 설치 및 시연 샘플 생성

저장소 루트에서 실행한다.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r demo/backend/requirements.txt
cd demo/frontend
npm install
cd ../..
python -m demo.fixtures.make_samples
```

샘플은 가상 값으로 만든 PDF이며 `demo/fixtures/samples/`에 생성된다. 시나리오 테스트는 해당 폴더가 없을 때 자동으로 생성한다.

### 전북AI OCR 벤치 환경

벤치 도구를 사용할 때는 로컬 환경변수에 `JBAI_BASE_URL`과 `JBAI_API_KEY`를 설정한다. 변수 이름은 [`.env.example`](.env.example)에 있다. 키가 든 `.env`는 저장소 루트에 로컬로 두고 커밋하지 않는다. OCR 백엔드는 `.env`를 자동으로 읽지 않으므로, 실행 프로세스에 환경변수로 전달해야 한다.

실제 서류 전송 허용 설정은 기본적으로 꺼져 있다. 기관의 개인정보 전송 승인이 있기 전에는 실제 서류를 외부 OCR에 보내지 않는다. 데모 업로드는 기존 OCR 흐름을 사용한다.

### 백엔드와 프론트엔드 실행

두 터미널을 사용한다. 백엔드는 저장소 루트에서 실행해야 한다.

```bash
# 터미널 1 — 저장소 루트
uvicorn demo.backend.main:app --reload --port 8000
```

```bash
# 터미널 2
cd demo/frontend
npm run dev
```

브라우저에서 <http://localhost:5173>을 연다. FastAPI 문서는 <http://localhost:8000/docs>에서 볼 수 있다.

## 확인 및 테스트

저장소 루트에서 시나리오 전체와 OCR 엔진 테스트를 실행한다. 테스트는 가상 데이터와 임시 저장소를 사용한다.

```bash
for f in demo/backend/tests/run_p*_scenarios.py; do python -m demo.backend.tests.$(basename "$f" .py) || exit 1; done
python -m pytest engine_v2/tests -q
```

프론트엔드 타입 검사·린트·빌드는 다음과 같이 확인한다.

```bash
cd demo/frontend
npx tsc -b && npx oxlint && npx vite build
```

하위 폴더별 기능 설명과 추가 실행 방법은 [`demo/README.md`](demo/README.md), [`engine/README.md`](engine/README.md), [`engine_v2/README.md`](engine_v2/README.md), [`dashboard/README.md`](dashboard/README.md)를 참고한다.

## 지켜야 할 원칙

- 실제 서류는 `engine_v2/data/private/`에만 두고 저장소에 커밋하지 않는다.
- 판정은 공고문에 근거한 규칙으로 하고, OCR·모델은 문서 내용을 읽는 데 사용한다.
- 신청자 화면에는 배점·내부 판단 정보·서류 속 타인의 이름을 노출하지 않는다.
- 파일 이름이 아니라 서류 내용으로 종류와 판정 근거를 판단한다.
- API 키를 코드·로그·커밋에 넣지 않는다.
- 기관 확인 전에는 실제 신청 서류를 외부 OCR로 보내지 않는다.

## 확인이 필요한 것

- 혼합가입자가 제출할 서류와 건강보험료 합산 방식
- 공고문 표가 7인까지인 상태에서 8~10인 상한표를 적용하는 출처·기준
- 취업지원패키지 지원 횟수 누적 범위와 인정 시험 목록
- 개인정보 측면에서 신청 서류 이미지를 전북AI OCR로 보낼 수 있는지
- 담당자 심사 상태를 승인·보완요청·부적격·재검토 4종으로 전환할지
