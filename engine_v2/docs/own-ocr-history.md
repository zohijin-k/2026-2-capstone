# 자체 OCR `own` 제작 과정

공개 저장소의 대회 심사위원·도청 담당자·후속 개발자를 위한 기록이다. 사실과 수치는 기존 문서·코드·작업 보고에서 가져왔으며, 날짜는 git 이력 기준이다. 아래 성능 표는 합성 서류 결과다.

용어: OCR=이미지의 글자를 텍스트로 읽기, Document AI=문서의 종류·항목·구조를 해석하는 기술, KV 추출=항목 이름과 값 뽑기.
용어: CER=글자 오류율(작을수록 좋음), 필드=성명·발급일 같은 개별 항목, 추론=학습된 모델로 새 입력을 처리하기, CPU=일반 프로세서.
용어: 벤치=같은 조건에서 성능을 재는 시험, 회귀 검증=수정 후 기존 동작이 깨지지 않았는지 확인하기, 정규화=입력 형식을 일정하게 맞추기.
용어: 미세조정=사전학습 모델을 새 자료로 추가 학습하기.
용어: 원근 보정=비스듬히 촬영된 문서를 평면 사각형으로 펴기, PP-OCR=공개 사전학습 OCR 모델 계열.
용어: ONNX=모델 교환 형식, ONNX Runtime=그 모델의 실행 도구, SHA256=파일 내용이 같은지 검사하는 해시, seed=난수 재현을 위한 시작값, API=프로그램 간 호출 인터페이스.

## 1. 왜 자체 OCR인가

수요기관 요구의 확정 원문은 확인한 저장소 자료에 없어 끝의 기록 없음 목록에 남긴다. 저장소에서 확인되는 방향은 공개 한국어 모델을 기관 내부 CPU에서 실행하고, own 추론 중 문서 이미지를 외부로 전송하지 않는 것이다. 모델 다운로드와 문서 추론은 분리한다.
`own`은 직접 사전학습한 인식 모델의 이름이 아니라, 공개 모델과 자체 처리 코드를 묶은 로컬 엔진 이름이다. 인식은 모델이 수행하고, 항목 연결·서식 검증·업무 판정은 규칙으로 구분한다. 근거: [기존 설계·실행 계약](own-ocr.md#기존-구조와-호환-계약), [own 코드](../pipeline/ocr/own.py).
전북AI(jbai)는 수요기관 제공 OCR API이며 별도 어댑터로 연결됨. 이 문서에서는 평가·비교하지 않는다.

## 2. 엔진 선정 과정

기존 [모델 선택 기록](own-ocr.md#모델-선택과-라이선스)에 있는 검토만 요약한다. 후보 간 실제 우열을 모두 측정한 기록은 없다.

| 검토 후보 | 저장소에 기록된 판단 | 결정 |
|---|---|---|
| PaddleOCR 공식 모델의 직접 ONNX 변환 | 직접적인 원본이나 변환 도구체인·검증이 추가로 필요 | 미선택 |

| monkt/paddleocr-onnx | 한국어 v5 제공, 검출 모델은 server(대형) 계열 | 미선택 |
| 이전 PP-OCRv3 Korean | 작은 구세대 후보; 품질 비교는 미측정 | 미선택 |
| Apple Vision / EasyOCR | 전자는 macOS 전용, 후자는 최초 합성 비교에서 미설치 | 공용 어댑터 유지; 측정 없는 우열 주장 안 함 |

일반 추출 진단은 값을 가려도 좌표를 포함할 수 있다. 엄격한 값·좌표 비출력은 `--safe-issue` 경로이며, 두 모드를 같은 보장으로 표현하지 않는다.
현재 공용 엔진 기본값은 macOS에서 Apple Vision, 그 외 own이며 환경변수 선택이 우선한다. demo의 비맥 기본값은 EasyOCR로 별도 유지된다. 이번 기록 작업은 연결·설정을 바꾸지 않는다.

## 4. 측정과 발견

기존 합성 평가의 첫 점검에서는 문자열 읽기 순서가 CER을 높이는 경우를 발견했다. 기존 21쪽을 다시 확인한 결과, 비영 CER 8건은 읽기 순서 문제였고 평가 순서를 고친 뒤 모두 CER 0이었다. 추출 필드 결과는 그대로였다. 이는 해당 합성 세트에만 해당한다.
개정 CER은 합성 정답의 행 위치와 변환 정보를 써서 인식 영역 순서를 복원한 글자 인식 지표다. 배포 엔진의 읽기 순서나 KV 추출 정확도와 구분해야 한다. 이후 명조·휴대폰 세트에서 나온 실제 대시 오인식과 배경 문자 삽입은 지우지 않았다.

아래는 `004e45a` 시점의 [휴대폰·보정 기록](own-ocr.md#휴대폰과-보정-비교)이다. 대시 추출 수정 이전 결과이며, 각 행은 합성 6쪽 집계다.

| 합성 조건 | 보정 적용 | 평균 CER | 필드 일치 합계 | 평균 초/쪽 |
|---|---|---:|---:|---:|
| 약한 휴대폰·보정 전 | 미요청 | 0.0082 | 7/32 | 1.244 |
| 약한 휴대폰·보정 후 | 6/6 적용 | 0.0010 | 30/32 | 1.500 |
| 강한 휴대폰·보정 전 | 미요청 | 0.0141 | 5/32 | 1.289 |
| 강한 휴대폰·보정 재시도 | 0/6 적용 | 0.0141 | 5/32 | 1.471 |

강한 조건의 재시도는 보정 성공이 아니라 동일 원본 재처리다. 처리 시간은 모델 첫 로드를 포함한 한 번의 실행 기록이며 준비 실행·반복 측정에 따른 안정된 속도 보장은 아니다. CER이 작아도 항목의 행·열 연결이 틀리면 필드 추출은 실패한다.

## 5. 실패 진단과 수정

근거: [합성 추출 진단](../../.trellis/tasks/11-11-classifier-diagnosis/extraction-diagnosis.md), [형식 수정 기록](own-ocr.md#대시-정규화와-4대보험-발급일-2026-11-11). 해결 여부는 기록된 합성 조건 범위다.

| 문제 | 원인 | 조치 | 상태 |
|---|---|---|---|
| 평가 CER 이상치 | 작은 좌표 차이로 문자열 행 순서 변경 | 평가용 기하 순서 복원, 기존 원시 순서 지표도 보존 | 해결 |
| 초본 이름·생년월일·주소이력 누락 | 하이픈이 다른 대시 문자로 읽혀 형식 매칭 실패 | 공용 대시 10종 정규화, 파싱 직전 복사본에만 적용 | 해결 |
| 4대보험 발급일 오선택 | 라벨이 있는 행 전체에서 왼쪽 도장 날짜 선택 가능 | 머리 표 라벨 오른쪽 같은 행만 사용, 빈칸·깨짐·라벨 누락은 값 없음 | 해결 |
| 건강보험 표 행·머리글 밀림 | 원근·영역 크기 차이로 행 분리, 날짜·금액 연결 오류 | 진단·약한 조건의 선택적 보정; 일반 행 연결 개선은 미실시 | 부분 |
| 건강보험 발급일 역할 혼동 | 조회기간 날짜가 발급일 행에 묶이는 경우 | 진단 완료; 4대보험 수정과 분리해 기존 동작 유지 | 미해결 |
| 강한 휴대폰 원근 | 외곽 검출 조건 불충족 | 실패를 명시하고 원본 유지; 정답 모서리로 대체 안 함 | 미해결 |
| 서류 종류 판별 | 기존 문구 규칙의 혼동, 학습 모델의 높은 보류율 | 독립 분류 모델 학습·평가, 운영 규칙 대체 보류 | 부분 |

합성 명조 초본을 own으로 재측정했을 때 clean(깨끗한 원본)·scan300(스캔 모사)·rotate(회전)가 각각 2/4→4/4, blur(흐림)가 3/4→4/4로 회복했다. 성명 문자를 고친 것이 아니라 주민번호·날짜의 형식 경로가 회복된 결과다. 슬래시·점 허용 범위, 성명·주소 원문, 주민번호 뒷자리 폐기와 판정·점수 규칙은 유지했다.

용어: 확률 보정=모델 점수를 실제 정답 가능성과 맞추는 절차, 임계값=자동 수용과 보류를 나누는 기준.

| 선택·막힌 지점 | 확인된 결과·결정 |
|---|---|
| 서류 분류 모델 운영 연결 | 19종, 학습 304쪽·시험 304쪽의 합성 실험. 고정 임계값에서 정확도 21.05%, 보류 78.95%; 기존 규칙 정확도 56.58%. 확률의 운영 적합성·보정이 검증되지 않아 운영에 연결하지 않고 보관 |
| 시험 결과를 본 뒤 임계값 낮추기 | 수행하지 않음. 향후 학습 자료 안에서만 검증·확률 보정하고 새 시험 자료로 재평가 |
| 인식 미세조정 | 공개 인식 가중치를 동결한 채 평가·추출 문제를 먼저 확인했다. 구체적인 연기 사유·일정은 기록 없음; 자체 분류 모델 학습과 구분 |
| 못 찾은 값 채우기 | 다른 위치의 그럴듯한 후보로 채우지 않고 담당자 확인으로 보낸다는 원칙. 4대보험 발급일에 적용했으며 기존 건강보험 미해결 경로의 개선 기준으로도 유지 |

분류 모델은 문자의 출현·희소도와 위치 특징의 가중합으로 서류 종류를 고르는 CPU 분류기다. 후보 순위의 정답률을 운영 정확도로 바꿔 부르면 안 된다. 확률 자체가 실서류 정답 보장은 아니다. 근거: [분류 문서](classifier.md#results-and-read-only-extraction-diagnosis), [실측 보고](../../.trellis/tasks/11-11-classifier-diagnosis/report.md).

## 7. 현재 한계와 다음 단계

합성 글꼴·배치를 나눴어도 내용 표현은 관련되어 있고 실제 기관별 서식 분포를 대표하지 않는다. 순수 인물 사진·알려지지 않은 서식, 강한 원근, 작은 표 숫자·긴 인식 영역·뒤집힘·손글씨는 추가 검증이 필요하다. 실서류 비교 결과는 여기서 보고하지 않는다.
아래는 이미 만든 기능이 아니라 **아직 안 한 학습형 후속 작업**이다.

| 후속 단계 | 현재 상태 | 기존 기록에 있는 다음 검증 |
|---|---|---|
| 인식 미세조정 | 미착수 | 한국어 인식 모델 우선 추가 학습, 모델 변환 후 CER·필드·시간 회귀 확인 |
| 분류 모델 운영 연결 | 미착수 | 학습 자료 안의 확률 보정·새 독립 시험; 기존 규칙 대체 여부 판단 |
| 담당자 수정 기반 재학습 루프 | 미착수 | 설계·데이터 관리·운영 검증 기록 없음; 완료 기능으로 표현하지 않음 |

| 써도 되는 말 | 쓰면 안 되는 말 |
|---|---|
| 공개 한국어 OCR 모델을 기관 내부에서 운영하는 자체 OCR 엔진, 전처리·보정·추출·검증은 자체 개발 | OCR을 직접 개발/학습했다 — 인식 미세조정 전까지 사용 금지 |
| 합성 세트·측정 조건을 붙여 CER과 필드 일치를 별도로 보고 | CER이 낮으므로 모든 서류 항목도 정확하다 |
| 서류 분류 모델은 합성 학습·독립 평가 완료, 운영 미연결 | 학습형 분류 모델이 운영에서 서류를 자동 판별한다 |
| 약한 합성 휴대폰 조건에서 선택적 보정 효과 확인 | 강한 촬영 조건도 모두 보정한다 |
| 값 비출력 모드가 제공되며 입력·출력 범위가 정해져 있다 | 일반 진단을 포함한 모든 출력에서 좌표까지 사라진다 |

## 9. 재현 방법

명령은 중복하지 않는다. [설치·모델 준비](own-ocr.md#설치와-실행), [합성 생성·학습/시험 분리](own-ocr.md#글꼴학습시험-분리휴대폰-생성), [휴대폰 보정](own-ocr.md#휴대폰과-보정-비교), [발급일 안전 진단](own-ocr.md#값-없는-발급일-안전-진단-mac)을 따른다. 분류 학습·독립 평가는 [분류 재현 문서](classifier.md#reproduce-on-cpu)를 따른다.
