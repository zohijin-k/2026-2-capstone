# 담당자 목록 서류 컬럼 + 상세 점프

## Goal

담당자 접수 목록(두배적금)에서 신청자가 낸 서류를 **서류 종류별 개별 컬럼**으로 보여주고,
각 칸을 누르면 상세 심사 화면이 **그 서류를 연 상태로** 열리게 한다.

지금은 목록에 `미비서류` **개수**만 있다. "3건 미비"를 보고도 어느 서류가 빠졌는지 알려면
건별로 상세를 열어 탭을 하나씩 눌러봐야 한다. 담당자가 목록에서 먼저 재고 싶은 것은
"이 사람이 무엇을 냈고, 그중 어디가 걸렸는가"다.

## Background — 무엇이 이미 있나

- 목록 컬럼은 서버가 주는 `list.columns` 배열을 헤더·셀이 **공유**한다
  (`ApplicationList.tsx:Cell`, `api/officer.py:LIST_COLUMNS`). 컬럼을 늘리는 자리는 이미 있다.
- 두배적금 업로드 서류는 `rules/required_docs.py:_double_savings_checklist`가 정한다:
  초본 / 건강보험료 납부확인서 / 건강보험 자격확인서 / 건강보험 자격득실확인서 /
  **근로확인서류(근로유형별 택1)** [+ 조건부: 근로계약서 사본, 자필 서식5, 2번째 사업장]
- 근로확인서류만 사람마다 서류명이 다르다 (`WorkCategory` 5종):
  직장가입자→4대보험 가입내역 확인서 / 지역가입자·피부양자→일용근로내역서 /
  사업소득 사업자→사업자등록증명 / 농업→농업경영체 증명서 / 어업→어업경영체 증명서
- 상세 화면은 좌측 **탭 방식**으로 서류 1장씩 본다 (`ReviewDetail.tsx`). 탭 방식은 유지한다.
- 담당자 화면은 백엔드가 없거나 접수 0건이면 **목업**으로 넘어간다 (`mock-data.ts`).
  현재 두배적금 목업 1건에는 서류가 `nhis_payment` **1장뿐**이라, 목업을 고치지 않으면
  새 컬럼이 전부 빈 칸으로 뜬다.

## Requirements

### R1. 목록에 서류 컬럼 (두배적금)

- R1.1 `미비서류` 컬럼 **오른쪽**에 서류 컬럼들이 붙는다. 순서는 체크리스트 순서를 따른다:
  `초본 · 건보료 · 자격확인 · 자격득실 · 근로확인서류 · 기타`
- R1.2 앞 4개는 모든 두배적금 신청자가 공통으로 내는 고정 서류다. 헤더가 서류명을 쥐므로
  칸에는 **상태 표시만** 들어간다 (적합 / 확인필요 / 부적합 / 미제출).
- R1.3 `근로확인서류` 칸에는 상태와 함께 **그 신청자의 실제 서류명**이 들어간다
  (예: "4대보험 가입내역 확인서", "사업자등록증명"). 사람마다 다른 유일한 칸이다.
- R1.4 `기타` 칸에는 고정 컬럼에 안 잡히는 나머지가 들어간다 — 근로계약서 사본,
  2번째 사업장 근로확인서류, 자필 서식5, 어느 슬롯에도 안 붙은 병합 페이지(미배정).
  없으면 빈 칸이다. 이 컬럼이 있어야 "목록에 안 보이는 서류"가 생기지 않는다.
- R1.5 `미비서류` 개수와 서류 칸의 상태는 **같은 계산**에서 나와야 한다.
  개수는 3인데 칸에는 문제가 2개만 보이는 일이 없어야 한다.

### R2. 칸 → 상세 점프

- R2.1 제출된 서류 칸은 클릭할 수 있다. 누르면 상세 심사 화면이 열리고
  **그 서류 탭이 선택된 상태**로 시작한다.
- R2.2 미제출 칸은 클릭 대상이 아니다 (열 원본이 없다).
- R2.3 행의 다른 곳을 누르면 지금처럼 첫 서류로 상세가 열린다. 서류 칸 클릭이
  행 클릭으로 번지지 않는다.
- R2.4 상세에서 `← 접수 목록`으로 돌아가면 목록의 필터·페이지가 그대로다 (현행 유지).

### R3. 취업지원패키지(선착순) 목록

- R3.1 선착순 컬럼셋은 이번 범위 밖이다. 항목별 서류가 회차마다 늘어나 컬럼으로
  고정할 수 없다 (면접비 3회 = 면접확인서 3장). `신청 항목` 컬럼을 그대로 둔다.
- R3.2 사업 필터가 `전체`인 화면에는 두배적금 컬럼셋이 뜨고, 그 안의 취업패키지 행은
  서류 칸이 비어 보인다. 이것을 오류로 보이게 두지 않는다 — 해당 사업 아님을 표시한다.

### R4. 목업 데이터

- R4.1 두배적금 목업 신청건이 체크리스트 **전 종류**의 서류를 갖는다.
  사람마다 `WorkCategory`가 정해지고, 그에 맞는 근로확인서류 1종이 붙는다.
- R4.2 서류별 판독값은 그 사람의 사실값(성명·생년월일·주소·전입일·가구원수·보험료·취업일)과
  **어긋나지 않는다**. 초본의 성명과 자격확인서의 성명이 다르면 시연이 무너진다.
- R4.3 `missing_count`가 서류 상태에서 **역산**된다 (지금은 난수라 칸과 따로 논다).
- R4.4 일부 신청건은 서류가 빠져 있다(미제출). 컬럼이 무엇을 위한 것인지 보이려면
  전건 완비여서는 안 된다.

### R5. 지키는 선

- R5.1 원본을 내려받는 경로를 새로 만들지 않는다 (R4.1 금칙). 칸 클릭은 상세 뷰어로 갈 뿐이다.
- R5.2 상세 뷰어는 **탭 방식 그대로**다. 연속 스크롤로 바꾸지 않는다.
- R5.3 목록 1페이지를 그리는 데 드는 서류 조회가 행 수만큼 늘지 않는다.
  지금 `_missing_count`가 행마다 `list_documents`를 한 번씩 부른다(N+1). 서류 정보까지
  행마다 다시 부르면 두 배가 된다 — 페이지 단위로 한 번에 읽는다.

## Acceptance Criteria

- [ ] AC1 두배적금 목록에 `초본 · 건보료 · 자격확인 · 자격득실 · 근로확인서류 · 기타` 6개 컬럼이 뜬다
- [ ] AC2 근로유형이 다른 두 신청자의 `근로확인서류` 칸에 서로 다른 서류명이 뜬다
- [ ] AC3 서류를 안 낸 신청자의 해당 칸이 `미제출`로 구분되어 보인다
- [ ] AC4 어떤 행이든 `미비서류` 숫자 = 그 행의 서류 칸 중 (미제출 + 적합 아님) 개수
- [ ] AC5 서류 칸을 누르면 상세가 열리고 **그 서류 탭이 선택**되어 있다
- [ ] AC6 미제출 칸을 눌러도 아무 일도 안 일어난다(행 클릭으로도 안 번진다)
- [ ] AC7 취업패키지 사업 필터에서는 기존 `신청 항목` 컬럼셋이 그대로다
- [ ] AC8 목업(`?mock=1`)에서 AC1~AC6이 전부 재현된다
- [ ] AC9 백엔드 실데이터(`?mock=0`, 시드된 신청건)에서도 AC1~AC6이 재현된다
- [ ] AC10 `npx tsc --noEmit` / lint / 백엔드 테스트가 통과한다
- [ ] AC11 화면 어디에도 파일 저장·다운로드 버튼이 새로 생기지 않았다
