# 데모 사이트 (신청자 신청 + 담당자 심사) 개발 계획 수립

## Goal

**전북청년 두배적금 및 취업지원패키지 신청서류 자동 검토 및 자격 심사 시스템**의 데모 사이트를 만들기 위한 요구사항·설계·실행계획을 확정한다.

데모 사이트의 범위는 두 화면군이다.

1. **신청자 화면** — 자격 자가진단 → 신청서 작성 → 동의 → 서류 업로드(즉시 판정) → 제출 → 마이페이지
2. **담당자 심사 화면** — 접수 목록 → 건별 심사(원본 뷰어 + AI 판독 결과 + 심사표 점수) → 승인/반려

대상 사업은 **두배적금**(점수제·보완불가)과 **취업지원패키지**(선착순·7일 보완) 2종이다.

## Requirements

### R1. 신청자 — 수기(手記) 0건

- R1.1 서식1(참여신청서), 서식2(자가진단·확인동의서), 서식3(개인정보 수집·이용), 서식4(제3자 제공)은 **전부 웹 폼/체크박스**로 처리하고 업로드를 요구하지 않는다.
- R1.2 서식5(행정정보 공동이용 사전동의서)는 원문상 `(서명또는인)` 자필서명 요구다. 데모는 **캔버스 전자서명 + 타임스탬프 + 동의 로그**로 대체하되, 화면에 "현행 지침은 자필서명 — 전자서명 전환 제안" 배지를 노출한다. 자필 스캔 업로드 모드도 토글로 병행 제공한다.
- R1.3 파일 업로드는 **발급받아야만 하는 서류**(주민등록초본, 건강보험 3종, 근로확인서류, 취업패키지 영수증·확인서)에만 허용한다.
- R1.4 취업패키지 '통장 사본'은 계좌번호 입력으로 대체한다(실명조회 API는 비목표).

### R2. 신청자 — 업로드 즉시 판정

- R2.1 파일 업로드 후 **5초 이내** `적합 / 부적합 / 확인필요` 중 하나를 인라인 표시한다.
- R2.2 부적합 시 **사유 + 해결 방법 + 발급처 링크 + 재업로드 버튼**을 함께 제공한다.
- R2.3 공고문이 직접 지목한 미비 유형을 최소한 전부 탐지한다: **파일 암호 미해제 / 초본에 과거 주소이력 미포함 / 초본 아닌 등본 제출 / 공고일 이전 발급분 / 모니터 화면 캡처**.
- R2.4 판정 근거가 된 원본 위치(`bbox`)를 함께 보관해 담당자 화면에서 하이라이트할 수 있게 한다.

### R3. 신청자 — 신청 난이도 최소화

- R3.1 자가진단(서식2 8문항)을 신청서 작성 **이전**에 배치해 부적격자를 진입 전에 걸러낸다.
- R3.2 근로유형 선택 결과에 따라 근로확인서류 5종 중 **본인에게 필요한 1종만** 체크리스트에 남긴다.
- R3.3 전입일·취업일·생년월일만 입력하면 거주기간·근로기간·연령을 **공고일(2026-03-03) / 2025-12-31 기준으로 자동 역산**해 서식1의 구간 체크를 대신한다.
- R3.4 임시저장 / 이어서 작성을 지원한다(서류 발급하러 이탈했다 복귀 가능).
- R3.5 **서류별 개별 업로드**를 허용한다. 공고문의 "1개의 파일로 압축하여 올려야 함" 규정은 현행 UX 부담이므로, 데모는 개별 업로드를 기본으로 하고 병합 파일 업로드 시 **페이지 자동 분리·분류**를 시도한다.
- R3.6 ~~모바일에서 동작한다~~ → **PC 전용으로 확정** (R8.6). 스마트폰 촬영 업로드는 비목표.

### R4. 담당자 — 다운로드 0회 심사

- R4.1 원본 파일은 `Content-Disposition: inline` 스트리밍 + pdf.js/이미지 뷰어로 **브라우저 안에서** 렌더한다. 다운로드 버튼을 두지 않는다.
- R4.2 좌측 원본 / 우측 AI 판독 결과의 **분할 뷰**로 구성한다.
- R4.3 심사표 항목 점수를 클릭하면 좌측 원본의 **해당 위치로 스크롤 + 하이라이트**된다.
- R4.4 접수 목록에서 사업·시군·처리상태·AI판정·신청일 필터와 점수순 정렬(두배적금) / 접수순 정렬(취업패키지)을 제공한다.
- R4.5 시행지침의 **읍면동 → 시군(120% 선발) → 도·청년허브센터(2차검증, 100% 확정)** 3단계 권한을 역할 전환 토글로 시연한다.

### R5. 심사표 자동 채점 (두배적금)

시행지침 서식6 배점표를 그대로 구현한다. 총 100점.

| 평가항목 | 배점 | 구간 → 점수 |
|---|---|---|
| 1. 중위소득 (가구소득) | 40 | 130%↑ **28** / 120~130% **31** / 110~120% **34** / 100~110% **37** / 100% 미만 **40** |
| 2. 도 거주기간 (전입일→공고일 역산) | 25 | 1년 미만 **15** / 1~2년 **17** / 2~3년 **19** / 3~4년 **21** / 4~5년 **23** / 5년↑ **25** |
| 3. 근로기간 (현직장 취업일→공고일 역산) | 25 | 1년 미만 **16** / 1~2년 **19** / 2~3년 **22** / 3년↑ **25** |
| 4. 신청자 연령 (2025-12-31 기준 만나이) | 10 | 35세↑ **7** / 30~34세 **8** / 25~29세 **9** / 24세 이하 **10** |

- R5.1 **동점자 우선순위**: ① 가구소득이 적은 자 ② 도 거주기간이 긴 자 ③ 근로기간이 긴 자 ④ 연령이 낮은 자. (※ '25년 순서와 다름 — '26년 지침 기준)
- R5.2 중위소득 구간은 **건강보험 자격확인서상 가구원수 + 납부확인서상 '25.10~12월 고지금액 평균**으로 판정한다. 실납부액이 아니라 **고지금액** 기준이다.
- R5.3 점수는 **신청자 화면에 절대 노출하지 않는다** (공고문: "평가결과는 공개하지 않음").

### R6. 취업지원패키지 분기

| 항목 | 두배적금 | 취업지원패키지 |
|---|---|---|
| 선발 | 점수제 100점 + 시군별 정원 | **선착순**, 예산 소진 시 조기마감 |
| 보완 | **불가** (미비 시 즉시 제외) | **7일 내 보완**, 미보완 시 후순위자 교체 |
| 연령 | 2025-12-31 기준 만 18~39세 (1986.1.1.~2007.12.31.) | 2026년 기준 18~39세 (1987.1.1.~2008.12.31.) |
| 소득요건 | 중위소득 140% 이하 | **없음** |
| 서류 인정일 | 2026-03-03 이후 | **2026-01-01 이후** |
| 신청 단위 | 1회 | **항목별 복수 선택 가능** |

- R6.1 지원 항목별 한도: 면접비 5만원/회 최대 2회 · 정장 대여비 5만원(실비) 최대 2회 · 면접사진 2만원(실비) 1회 · 자격증 응시료 5만원(실비) 최대 2회.
- R6.2 실비 항목은 **영수증 금액과 한도를 비교**해 실지급액을 계산한다 (예: 정장 35,000원 → 35,000원 / 70,000원 → 50,000원).
- R6.3 선택한 항목에 따라 추가서류 체크리스트가 조립된다 (면접확인서 / 결제영수증 / 면접용 사진사본 / 응시확인서·성적표(**응시일 표기 필수**)).

### R7. 데이터·개인정보

- R7.1 데모는 **더미 데이터만** 사용한다. 실제 신청자 데이터, 실물 서류는 일절 사용하지 않는다.
- R7.2 서류 파일과 DB는 저장소에 커밋하지 않는다(`.gitignore`).

### R8. 서식 원형 재현 (Must)

- R8.1 신청자가 보는 입력 화면은 **PDF 서식의 표 구조·항목 순서·문구를 그대로** 따른다. 일반적인 웹 폼으로 재구성하지 않는다.
- R8.2 서식 원문의 각주(`※ 전북특별자치도 최종전입일로부터 공고일까지 기간` 등)와 안내 문장을 **원문 그대로** 유지한다.
- R8.3 서식의 `□` 체크 항목은 체크박스 형태를 유지한 채 실제 입력 컨트롤로 동작한다.
- R8.4 **서식 구조와 단계별 입력이 충돌하면 안 된다.** 위저드 스텝 경계를 서식1의 절(Ⅰ~Ⅳ) 경계와 일치시키고, "서식 전체 보기" 토글로 한 장 전체를 펼쳐 볼 수 있게 한다.
- R8.5 자동계산 항목(거주기간·근로기간 구간)은 서식의 체크박스를 **그대로 그리되 자동 선택 + 읽기전용 + 근거 문장**을 붙인다. 형태는 보존하고 오선택 여지는 없앤다.
- R8.6 **이 사이트는 PC 전용이다.** 열 너비와 체크박스 줄바꿈 위치를 원본 PDF와 동일하게 고정하고, 좁은 화면에서는 셀을 재배치하지 않고 가로 스크롤만 허용한다. 반응형으로 셀을 쌓으면 "종이 서식과 같은 구조"가 깨진다.
- R8.7 담당자 화면의 심사표는 **서식6 원본 배점표 레이아웃**으로 렌더한다. 담당자가 쓰던 종이 심사표와 시각적으로 같아야 학습 비용이 0이다.
- R8.8 날짜는 **년·월·일을 각각 따로** 받는다. 서식의 칸이 원래 그렇게 나뉘어 있고, 브라우저 기본 date 피커를 쓰면 칸 안에 이질적인 위젯이 들어가 서식 모양이 깨진다.
- R8.9 표의 열 너비는 눈대중이 아니라 **원본 PDF의 실제 표 선 좌표**에서 뽑아 쓴다.

### R9. 작성 서식의 PDF 내보내기 (Should — 메인 아님)

- R9.1 작성 완료된 서식을 **원본 서식과 동일한 형태의 PDF**로 저장할 수 있다.
- R9.2 서식5는 전자서명 이미지가 서명란 위치에 합성되어야 한다.
- R9.3 담당자도 **다운로드 없이** 브라우저에서 확인 가능해야 한다 (`Content-Disposition: inline`).
- R9.4 **우선순위는 최하위(P7)**. 미구현 시에도 데모의 수용 기준(DoD)에 영향을 주지 않는다. 데모에서는 서식1·서식5 **2종만** 구현한다.

## Constraints

- C1. **산출물 위치**: 이 데모가 만드는 모든 파일은 저장소 루트에 새로 만드는 **`demo/` 폴더 안에만** 둔다 (`demo/backend/`, `demo/frontend/`, `demo/fixtures/`, `demo/storage/`).
  - 엔진(`engine/`)은 **진** 담당, 대시보드(`dashboard/`)는 **채운** 담당이다. 두 폴더와 저장소 루트에는 **파일을 추가하거나 수정하지 않는다.**
  - 허용 예외 2가지: 루트 `.gitignore` 항목 추가, `docs/demo-site-dev-plan.md` 갱신.
  - `engine/`은 복사하지 않고 `sys.path`를 통해 import한다. 진의 수정이 그대로 반영되어야 한다.
  - 이유: 3인 공동 저장소라 최상위 이름 충돌과 의존성 파일(`package.json`, `requirements.txt`) 경합을 원천 차단해야 한다.
- C2. 현재 `engine/config.py` 값이 공고문과 불일치한다(초본/등본 반전, 서류 목록, 발급 기준일, 소득분위 vs 중위소득%). **엔진 수정 요청 목록**을 산출물로 만들어 공유하되, 데모는 어댑터 레이어를 두어 엔진 변경과 무관하게 진행한다.
- C3. 실제 본인인증(PASS/공동인증서), 상용 OCR API, 행복e음·일모아 연동, 알림톡 발송은 **비목표**. 인터페이스만 정의한다.
- C4. 통계·시각화는 대시보드 영역. 데모의 담당자 화면은 **건별 심사**까지이며, 목록 화면의 정원 대비 진행률 배지가 경계선이다.
- C5. 서식 번호가 공고문과 시행지침에서 **다르다**. 문서·코드에서는 **시행지침 번호**(서식1=참여신청서, 서식2=자가진단)를 단일 기준으로 쓰고, 공고문 번호(서식1=자가진단, 서식2=참여신청서)는 대조표로만 남긴다.

## Acceptance Criteria

이 태스크(계획 수립)의 완료 조건이다. 구현 완료 조건은 `implement.md`의 DoD를 따른다.

- [ ] `docs/demo-site-dev-plan.md`가 정식 프로젝트명으로 갱신되고, 모든 업무 규칙이 PDF 원문과 대조 검증되어 있다
