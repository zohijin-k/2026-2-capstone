# 두 사업 신청 서식 PDF 위 직접 작성

## 목표

두 사업의 신청 서식을 원본 PDF 페이지 위에서 작성하고, 작성본 미리보기·수정·초기화·서명 재작성 흐름을 제공한다. 기존 저장 JSON 키와 제출 판정 규칙을 유지한다.

## 단계 1 — 템플릿·좌표 맵·내보내기

- 공식 원본에서 두배적금 공고문 서식1~5와 취업패키지 신청서·동의서·면접확인서 템플릿을 만든다. 각 쪽은 A4 세로이며 제목 문자열로 검증한다.
- 공고문 서식 번호와 기존 내부 식별자 대응표는 한 위치에 둔다.
- 신청자 입력 칸 좌표를 저장 키에 맞춰 기록하고, 취업패키지 인쇄 예시 영역을 함께 기록한다.
- 두 사업 신청자 서식의 렌더링·담당자 작성본 목록을 지원한다.
- 좌표 존재·쪽 안 배치·입력 상자 겹침·렌더 결과 글자 위치·예시 글자 제거를 가상 값으로 검증한다.

## 단계 2 — PDF 작성 팝업

- 서식 목록에 작성 상태와 작성·미리보기·수정·처음부터 다시 동작을 둔다.
- 공통 팝업에서 원본 PDF를 배경으로 입력·체크·동의·서명을 받고, 필수 누락 이동·키보드 순서·라벨·다쪽 이동·넘침 안내를 지원한다.
- 자동 저장 키와 기존 자가진단·동의·지원 항목 검증을 유지한다.
- 취업패키지 시군 선택과 면접 회차 연결을 제공하고 정장비만 신청도 가능하게 한다.
- 업로드 단계에서 신청자 정보가 미리 들어간 면접확인서 양식을 보여 주며 회사 작성 칸은 비워 둔다.
- 완료본은 화면 안 미리보기로만 표시한다. 제출 후 편집·초기화는 API에서도 거부한다.
- 기존 서식 웹 폼 화면과 쓰이지 않는 스타일을 제거하고 담당자 작성본에서 모든 신청자 서식을 보여 준다.

## 완료 기준

- 단계별로 지정된 두 커밋을 만든다.
- 루트 원본 PDF와 개인 정보·API 키는 커밋하지 않는다.
- 좌표 및 PDF 렌더 테스트, 전체 백엔드 시나리오, 엔진 테스트, 프론트 타입·린트·빌드를 실행한다.
- 단계 2 화면을 합성 값으로 채워 각 서식 오버레이 위치를 시각 확인한다.
