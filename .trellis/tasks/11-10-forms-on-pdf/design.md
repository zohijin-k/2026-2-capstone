# 설계

## 핵심 경계

- 원본 페이지 선택·템플릿 산출·좌표 맵 생성은 `demo/fixtures/`에서 수행한다. 페이지 제목과 페이지 크기를 생성 시 검증한다.
- 공고문에 표시되는 서식 번호와 기존 내부 식별자를 `demo/fixtures/`의 단일 명시적 대응표에서 관리한다. 저장된 `form1_json`, `self_check_json`, `form5_json`, `consent` 키는 유지한다.
- 백엔드 `demo/backend/forms/`는 좌표 해석, 기존 저장 모델 값 조립, PDF 렌더링 및 편집 잠금의 단일 진입점이 된다.
- 프론트엔드는 공통 원본 PDF 팝업을 사용한다. 좌표는 A4 PDF point를 실제 렌더 배율로 환산하며, 작성·완성 미리보기 모두 동일한 산출 렌더러를 사용한다.
- 면접확인서는 신청서 저장 데이터가 아니라 템플릿 기반 출력 전용 양식이다. 회사 입력 영역은 빈 상태로 둔다.

## 1단계 흐름

원본 페이지 → 제목/페이지 크기 검증 → 페이지별 PDF 템플릿 → 텍스트·벡터 기반 좌표 생성 → 기존 값 builder로 PDF overlay → PDF 재열기 검사.

기존 2-up용 절단 로직은 제거한다. 템플릿 출력 이름과 내부 서식 식별자를 분리하며, 현재 두배적금 저장 키와 신청자 서식 내용을 연계한다. 좌표를 자동으로 특정할 수 없는 필드는 묵시적으로 생략하지 않고 실패 목록으로 보고한다.

## 2단계 흐름

신청서 단계에서 서식 목록 → 서식별 공통 작성 팝업 → 현재 저장값 fetch → 템플릿 위 입력 → 자동 저장 → 동일 렌더러 기반 미리보기. 서명 저장은 기존 consent 서명 저장 경로를 재사용한다. 작성 중 상태는 필수 키 충족으로 계산하고 서버 응답으로 동기화한다.

제출 뒤 API patch/reset은 HTTP 409로 거부한다. 미리보기는 인라인 PDF 응답이며 파일 다운로드 제어를 추가하지 않는다. 기존 검증 API는 입력값이 같은 JSON 키에 저장되므로 그대로 실행한다.

## 취업패키지 특이사항

- 신청분야는 기존 지원 항목 회차 상태와 동기화한다.
- 면접 회차별 회사·시군·면접일·직군을 현재 신청 데이터 및 연결 회차에서 채운다. 정장비만 신청한 때는 직접 입력 필드를 유지한다.
- 시·군 옵션은 서버가 제공하는 전북 시군 목록을 사용한다.
- 면접확인서 출력은 신청자 성명·생년월일·주소·연락처·이메일만 채우고 회사 정보는 비운다.

## 테스트 전략

- 1단계 테스트: 템플릿 8종, 좌표 키/경계/겹침, PDF 글자 위치, 원본 예시 글씨 제거, PDF 헤더·페이지 수.
- 2단계 테스트: 기존 시나리오 전체, 저장·초기화·제출 잠금·인라인 미리보기, 시군 검증, 정장비 단독 저장·판정.
- 화면 QA: 각 서식의 모든 입력 가능 칸을 가짜 값으로 채운 캡처를 렌더링하고 원본 선과 오버레이를 대조한다.
