**게이트**: ✅ **통과 (2026-09-16)**
- `python -m demo.backend.tests.run_p5_scenarios` — 146개 검증 항목 전부 통과 (실패 0)
- **S10 재현**: 면접비 2회 + 정장 1회 + 자격증 1회 복수 신청 → 지급 예정액 **193,000원**
  (면접비 50,000×2 정액 + 정장 **70,000원 → 50,000원** + 자격증 43,000원).
  근거 문장이 그대로 저장·표시된다 — "영수증 70,000원 > 한도 50,000원 → 50,000원 지급"
- 실비 경계값: 정장 35,000→35,000 / 50,000→50,000 / 70,000→50,000, 사진 18,000→18,000 / 25,000→**20,000**, 응시료 43,000→43,000 / 60,000→**50,000**. 면접비는 영수증 없이(또는 10,000원이어도) 회당 **50,000원 정액**
- 횟수 상한: 면접비 3회 신청 → 2회로 조정 + "최대 2회" 경고, 사진비 2회 → 1회. 실비 항목은 영수증 금액 미입력 시 `pending`으로 남고 제출이 막힌다
- **사업 분기**가 값으로 갈린다: 연령 기준일 2025-12-31 ↔ 2026-01-01, 출생범위 1986~2007 ↔ 1987~2008, 인정일 2026-03-03 ↔ 2026-01-01, 소득요건 有 ↔ 無, 근로요건 有 ↔ 無, 선발 점수제 ↔ 선착순, 보완 불가 ↔ 7일, 정원 1,300(시군별) ↔ 900(총량)
- **자가진단 8문항 → 2문항**. 취업패키지에서 2문항만 답해도 완료, 같은 답을 두배적금에 넣으면 미완료. 2번 부적격 사유가 취업패키지 기준(1987.1.1.~2008.12.31.)으로 나온다
- **체크리스트 조립**: 항목 미선택 시 공통 3줄(신청서·초본·통장사본) 중 업로드는 초본 1종뿐. S10 선택 시 7슬롯으로 늘고, 사진비만 남기면 3슬롯으로 준다. 신청서=온라인 작성, 통장사본=계좌번호 입력으로 갈음(R1.4)
- **응시일 표기 필수**: 응시일 없는 응시확인서 → `MISSING_REQUIRED_FIELD` **FAIL** + 해결 방법 제시. 응시일 있는 응시확인서·성적표는 둘 다 같은 슬롯에서 `PASS`(택1), 엉뚱한 서류는 `WRONG_DOCUMENT_TYPE` 하나만 뜬다
- **선착순·보완**: 접수 순번 1번/900건(남은 899), 확인필요 서류가 있는 건은 제출 즉시 보완 기한 D-7이 잡히고 보완 대상 서류가 지목된다. 두배적금은 두 블록 모두 `null`
- 점수제가 아니므로 `total_score`는 `None`, 심사표 `{}`. 소득요건이 없어 엔진 2단계도 `PASS`. 마이페이지 응답의 금지 키 0건
- 담당자 화면: 취업패키지는 **접수순** 기본 정렬 + 총량 진행률 배지, 자격요건은 거주지·연령 2항목, 항목별 지급 내역과 보완 기한 카운트다운이 뜬다. 두배적금은 점수순 유지
- **다운로드 0회 유지**(P4 DoD): 취업패키지 서류 원본도 전부 `Content-Disposition: inline`
- 회귀: `run_p2` 48/48 · `run_p3` 109/109 · `run_p4` 165/165 전부 통과 유지
- `tsc -b` · `oxlint` · `vite build` 무경고 (exit 0)
- 검증 스크립트는 DB·storage를 임시 경로로 격리 — `demo/demo.db`·`demo/storage` mtime 변화 없음
- `git status`에 `demo/` 외 신규·수정 파일 없음

**P5에서 남긴 것**
- 취업패키지 **신청서·자가진단 서식 원본이 사업계획서에 없다.** 항목 구성은 데모가 정한 것이고 화면(`FormJobApplication` 안내문·자가진단 각주)과 코드(`ProgramConfig.notes`) 양쪽에 `(데모 추정치)` 라벨을 달았다. TF에서 실제 서식을 받으면 서식1처럼 원본 표 구조로 교체한다
- 결제영수증 판독 금액(`결제금액`)과 신청자가 입력한 영수증 금액의 **교차 검증은 하지 않는다.** 지급액은 입력값 기준으로 계산되고, 판독 금액은 담당자 화면에 근거로만 보인다
- 후순위자 **자동 승계**는 구현하지 않았다. 보완 기한 만료를 화면에 표시하는 데까지다 — 승계는 담당자 판단(승인/반려) 뒤에 오는 운영 절차라 데모 범위 밖으로 둔다
