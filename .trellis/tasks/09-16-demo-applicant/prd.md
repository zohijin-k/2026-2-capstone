# 신청자 화면 — 신청 골격·서식 재현·업로드 즉시판정·통합심사

**부모 태스크**: `.trellis/tasks/09-16-demo-site/`
**담당 Phase**: P0 ~ P3
**요구사항 원본**: 부모 `prd.md` R1·R2·R3·R5·R7·R8 / 설계는 부모 `design.md`

## Goal

신청자가 **수기 0건**으로 두배적금 신청을 끝내고, 발급 서류만 올리면 **즉시** 적합 여부를 안내받는 구간을 완성한다. 화면은 PDF 서식의 구조·순서·문구를 그대로 따른다.

## Scope

| 포함 | 제외 |
|---|---|
| `demo/` 스캐폴딩 (P0) | 담당자 화면 전체 → `09-16-demo-officer` |
| 서식1~5 원형 재현 웹 폼 (P1) | 취업지원패키지 분기 → `09-16-demo-jobpkg` |
| 조건부 서류 체크리스트 + 업로드 즉시 판정 (P2) | fixture 10종·시연 대본 → `09-16-demo-jobpkg` |
| 엔진 연동 + 심사표 100점 채점 + 마이페이지 (P3) | 서식 PDF 내보내기(P7) → `09-16-demo-jobpkg` 선택 |

> 대상 사업은 **두배적금 단일**. 사업 분기 구조(`ProgramConfig`)는 P0에서 만들되, 취업패키지 값 채우기는 형제 태스크가 한다.

## Acceptance Criteria

- [ ] `demo/` 폴더 안에서 `uvicorn` + `vite dev`가 동시에 뜨고, `git status`에 `demo/` 외 신규 파일이 없다 (`.gitignore`·`docs/` 제외)
- [ ] 파일 업로드 0건 상태로 [자가진단] → [신청서] → [동의]를 완주할 수 있다
- [ ] 서식1~5 화면이 PDF 원본과 **항목 순서·각주 문구·체크 옵션 개수까지** 일치한다
- [ ] 위저드 스텝 경계가 서식1의 절(Ⅰ~Ⅳ) 경계와 일치하고, "서식1 전체 보기" 토글이 동작한다
- [ ] 전입일·취업일을 넣으면 서식의 구간 체크박스가 **자동 선택 + 읽기전용**이 되고 근거 문장이 붙는다
- [ ] 모바일(<1024px)에서 항목 순서가 유지되고 가로 스크롤이 발생하지 않는다
- [ ] 근로유형을 바꾸면 요구 서류 목록이 자동으로 바뀐다
- [ ] 업로드 후 **5초 이내** 적합/부적합/확인필요가 인라인 표시된다
- [ ] 시나리오 S3~S6(등본 오제출 / 발급일 이전 / 입력일 불일치 / 암호 PDF)이 재현된다
- [ ] 심사표 100점이 시행지침 서식6과 **수기 검산에서 일치**한다 (S2 = 99점, S7 = 부적합)
- [ ] 마이페이지 어디에도 심사 점수가 노출되지 않는다
- [ ] 실제 개인정보·서류 파일·DB가 커밋되지 않았다

## Notes

- 엔진(`engine/`)은 수정하지 않는다. `demo/backend/engine_adapter.py` 런타임 오버라이드로 흡수한다 (부모 design.md 8절).
- 엔진 수정 요청(E1~E13)은 P0에서 진에게 **공유만** 한다. 반영을 기다리지 않는다.
