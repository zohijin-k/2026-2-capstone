# Value-free explicit-input benchmark

The positional file mode of `python -m engine_v2.tools.ocr_bench` requires `--gt` and accepts `--doc resident_abstract|nhis_payment|nhis_acquisition_loss`, `--engines own applevision jbai`, optional `--today YYYY-MM-DD`, optional `--env-file .env`, and optional `--out metrics.json`. No output file or directory is created by default. `--output` remains synthetic-only. Existing OCR/extractors are unchanged.

Output schema: fixed engine IDs, generic allowlisted make_gt field keys, O/X flags and numeric metrics only. `input_failed`, `output_failed`, `skipped`, `failed`, `fallback`, field `match`, and `confidence_available` use O/X. Reason codes: 0 none, 1 platform, 2 dependencies/model, 3 credential, 4 JBAI real-document opt-in missing, 5 engine/extractor exception. No exception type, message, input path, value or OCR text is serialized. Unknown input keys/engine IDs are rejected without echo. Native fd 1/2 and Python stdout/stderr are discarded around input, inference and optional output operations; native buffers flush before restoration on success/error. This suppression is process-global, suitable for this single-threaded CLI only.

PDF pages are rasterized at 300 dpi even if a text layer is present, preventing accidental OCR bypass. Local confidence is mean emitted-word score; unavailable remote confidence uses -1 plus `confidence_available: X`. Seconds/page includes engine initialization/inference and extraction; input rasterization is excluded, so results are an OCR/extraction benchmark rather than complete ingestion latency. Remote JBAI retains `JBAI_ALLOW_REAL_DOCS=true` opt-in on all input paths. The benchmark never substitutes another engine; unexpected engine IDs mark fallback and failure.

Field matches compare serialized extracted values exactly. Scalar CER shares NFC/Unicode-whitespace normalization with synthetic CER. Structured CER uses value-only streams: history rows retain source order and category/acquired/lost column order, query periods retain start/end order, monthly dictionaries sort by month and concatenate each month and its amount. Fixed JSON property names and punctuation never contribute correct characters. Empty cells use a single explicit ␀ placeholder; a missing entire field is the empty string. The separator is a newline, removed by the existing whitespace rule. Monthly date keys are document data and remain in CER. All annotated monthly values are evaluated, rather than only the three-month average. Acquisition history/period reuse the existing structured extracted field. Bool CER compares true/false. Exact O/X still compares complete structured values, preserving boundaries even where concatenated value streams coincide. `address_contains` explicitly specifies partial annotation: substring edit distances are summed over annotated parts and divided by their total character count. `move_in_dates` is likewise a partial inventory: exact membership O/X and mean nearest-date CER over annotated dates; extra unannotated dates are not penalized. These partial-field CERs must not be interpreted as full-address/history CER.

New tests (existing files untouched) exercise noisy Python/native stdout/stderr, buffered native output on exceptions, continuation after engine failure, invalid input/key/argument non-echo, save-only-on-request, output collision protection, skips and remote opt-in, all make_gt field schemas, PDF text-layer rasterization, and actual own inference of a synthetic image with full stdout/stderr/output-file leakage checks.

Initial privacy test run: 10 passed in 3.31s; added value-only structured CER regression afterward.

Final component verification: 11 passed in the new privacy test file. Actual synthetic CLI example saved only by explicit --out in /tmp/own-private-bench-example/numeric.json: own 1.571746 sec/page, confidence 0.9950857073, name X/CER 0.5, birth_date O/CER 0, issue_date O/CER 0; applevision skip code 1; jbai skip code 3. All values and recognized text absent.
