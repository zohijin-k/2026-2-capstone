# 공단 발급 양식 지원 계획

상태: 2026-11-13 사용자 구현 승인. 기준 소스 e63bdb6. 아래 확정 결정과 확장 설계가 이전 계획의 미확정 선택지·다쪽 가정보다 우선한다.

## 1) 목적과 범위 / 범위 밖
공단 자격득실확인서를 본문·좌표에 따라 인식하고 필드를 추출하며, 구조 미판독과 신원 불일치를 검토로 연결한다. 정부24의 기존 알려진 양식 동작을 보존한다. 이번 산출 범위는 합성 재현·코드 조사·계획 문서뿐이다.

실서류, own OCR 개선·학습, 범용 PDF 파서 교체, 전체 건강보험 정책 개편, 파일명 분류, 표시/UI 수정, 운영 배포, 푸시·PR은 범위 밖이다. OCR 사슬/표시 원인에 관한 추가 구현은 6절의 선택사항이다.

## 2) 재현 결과와 원인
정본: [research.md](research.md). 동일 합성 공단 PDF는 직접 판독/업로드 모두 localocr(엔진 pdftext), 자격득실, 신뢰도 0.90, 발급일·생년월일 있음/성명 없음, 8/8이었다. 자격확인서 슬롯은 FAIL/WRONG_DOCUMENT_TYPE, 자격득실 슬롯은 PASS/경고 없음이다. expected를 바꾸거나 파일명을 바꿔도 같다.

화면의 두 경고 조합은 동일 PDF로 재현되지 않았다. 제목만 자격확인서로 바꾼 대조군에서는 pdftext 계층, 발급일·성명 미판독, NEEDS_REVIEW/두 경고가 나왔다. LocalOcr에 예외만 강제한 실험은 종류를 바꾸지 못했다. 화면 원인을 이 실험으로 확정하지 않는다(추정 후보와 확인 방법: research.md).

확정된 결함은 성명 라벨 옆 주민등록번호 머리글을 이름으로 읽는 것(nhis_common.py:138), 안전 필터가 사슬 끝에서 지우는 것(ocr/__init__.py:78), 지운 뒤 검증/신뢰도는 재계산하지 않는 것이다. 이 때문에 신원 필수값이 없는데 올바른 슬롯에서 통과할 수 있다(identity.py:39; doc_check.py:612). 또한 공단 발급번호 미지원(nhis_acquisition_loss.py:93), 번호·마커 검사 부재(:268), 사업장 추출에 날짜 혼입(:185)을 확인했다. 생년월일과 하단 발급일은 기존 로직으로 읽혔으므로 새로 실패한다고 가정하지 않는다.

표시 문자열은 실제 detected_doc_type이다(DocumentUpload.tsx:123 → common.py:211 → documents.py:233). 기본 두 NHIS 슬롯은 별개 종류를 요구한다(required_docs.py:368). 공고일과 같은 날은 통과한다(criteria.py:189; engine/stage1_document_check.py:45). 이 현재 정책을 이번 구현에서 자동으로 바꾸지 않는다.

## 3) 설계
### 본문 기반 양식 판별
- 문서 종류 판별과 양식 판별을 분리한다. 기존 자격득실 제목 판별 뒤 내부 form_kind를 government24 / nhis / unknown으로 둔다. 기존 OCR의 expected나 파일명은 사용하지 않는다.
- NHIS 후보: 자격득실 제목 + 발급번호 라벨/G와 18자리 값 + 확인청구자 표/성명·주민등록번호 헤더의 좌표 관계. 값이 훼손돼도 양식 레이아웃을 식별할 수 있도록 '양식 단서 확인'과 '번호 값 유효'를 별도 검사한다.
- government24 후보: 자격득실 제목 + 문서확인번호 라벨과 기존 머리글 구조. 단일 번호가 안 읽혀도 양식 단서는 남을 수 있다. 번호의 유효성은 별도 필수 검증이다. 실제 기존 정부24 회귀 자료가 가진 본문 단서를 먼저 목록화하고 기존 알려진 양식을 새 규칙에서 누락하지 않는다.
- 양식 단서가 모자라거나 서로 충돌하면 unknown으로 기록하고 REQUIRED_FIELD_UNREADABLE/NEEDS_REVIEW를 낸다. 기존 제목 분류를 슬롯 종류로 덮어쓰지 않는다. 문서 종류 불일치는 기존 WRONG_DOCUMENT_TYPE 우선 정책을 유지한다.

### 공단 필드 추출
- 성명: 확인청구자 블록에서 성명·주민등록번호의 헤더 행과 그 아래 값 행을 찾는다. 열 경계는 헤더/셀 좌표로 정한다. 같은 헤더 행·주민등록번호 헤더·이력/안내 문구를 후보에서 배제하고 성명 열의 값만 읽는다. 후보 없음/복수/머리글만 있으면 비운다. 페이지 아래를 무제한 탐색하지 않는다. 최종 추출 결과의 성명 필드와 bbox를 내보낸다.
- 생년월일: 주민등록번호 값 셀만 후보로 제한한다. nhis_common.py:189의 마스킹 허용과 :198의 세기 판정을 작은 공통 함수로 분리해 기존 generic header와 공단 경로가 함께 사용한다. 1/2/5/6→1900, 3/4/7/8→2000을 그대로 유지하며 잘못된 날짜/불명 숫자는 미판독이다. 중복 로직을 만들지 않는다.
- 발급일: 기존 _closing_issue_date를 활용하되 NHIS는 '건강보험 자격득실내역…위와 같이 확인합니다' 문장 밑, 이사장 위의 날짜 단독 줄을 좌표로 제한한다. 현재 함수는 이사장 뒤 두 줄까지 충돌 후보를 검사하므로 이 보수적 동작을 보존할지 회귀로 확인한다. 발급일 누락·복수·날짜 충돌은 미판독, 이력 표나 직인 날짜로 대체하지 않는다. 기존 라벨 날짜/정부24 경로는 유지한다.
- 발급번호: 발급번호 라벨 바로 오른쪽의 G+18자리만 정규화한다(공백·구분 부호 정리, G 보존). 쪽 간 비교를 위한 결과 객체 내부 메타데이터로 유지하고 신청자 필드/로그에 원문을 내보내지 않는다. 번호 값이 없거나 패턴이 불완전하면 필수 검토 사유다. 기존 문서확인번호 처리·비노출 계약을 재사용한다.
- 이력: No/가입자구분/사업장명칭/취득일/상실일 헤더를 찾아 열 구간과 표 시작/끝을 정한다. 단어는 y 중심/행 높이로 묶는다. 번호를 별도 보관하고 가입자구분 4종을 내부적으로 구별한다. 데모의 기존 가입구분 직장/지역 표현이 필요한 경우 명시적으로 변환한다.
- 날짜 열의 날짜 패턴·단어 좌표를 먼저 배정하고 그 단어를 사업장 후보에서 제거한다. 빈 사업장 셀은 빈 문자열이며 뒤 날짜를 옮기지 않는다. 사업장 좌측 시작점이 헤더 중심보다 왼쪽이어도 열 안의 글자는 보존한다. 괄호/쉼표/공백이 있는 긴 사업장명, 날짜 열을 가로지르는 토큰은 날짜 셀 후보를 우선 분리하고 중복 배정하지 않는다. 분리가 모호하면 검토 처리한다. 사업장 원문은 현재처럼 내부 row 객체에만 두고 출력·경고로 확대하지 않는다.

### 판독검증과 검토 연결
NHIS 구조 검사 목록을 eligibility 검사(최근 5년 포함 등)와 분리한다.
- 양식 식별/첫 쪽 성명·생년월일 추출/성명 헤더 제외.
- 발급일의 확인문장–날짜–이사장 순서와 유일성.
- 모든 실제 이력 행에 번호·가입자구분·취득일이 존재하고, 번호는 1부터 중복/누락 없이 연속.
- 최신 1번 행의 상실일 공란, 각 행 취득일≤상실일, 아래 행 상실일=바로 위 행 취득일.
- 이하여백 마커 존재 및 위치, 마커 뒤의 이력 후보 없음.
- 발급번호·쪽 표시 인식 및 쪽 간 일치/전체 수 일치.

기존 common.Validation을 사용한다. 성명·발급일 같은 값 부재도 failed validation을 반드시 남긴다. 원시 성명이 header-only인지 추출 단계에서 걸러 이미 거짓 성명 검증이 생기지 않게 한다. 필수 필드/구조 검증 실패는 _from_nhis 변환 시 최소한의 완전성 검사로 confidence≤0.4 및 검토 사유를 보존하고, doc_check의 자격득실 분기가 REQUIRED_FIELD_UNREADABLE로 연결한다. 이름이 없는데 다른 필드 신뢰도만으로 PASS할 수 없어야 한다. 사슬의 공통 안전 필터는 보존한다.

검증 실패를 모두 업무적 부적합으로 취급하지 않는다. 구조가 불완전할 때는 5년 미포함 등 이력 기반 FAIL을 먼저 내지 않도록 자격득실의 완전성 검토를 선행한다. 구조가 확실한 서류의 실제 5년 조건 판정은 기존 동작을 유지한다. 신뢰도 하향만으로 검토 사유가 사라지지 않도록 API 경로에서 최종 상태까지 확인한다.

### 여러 쪽
현재 첫 쪽 신원 요구·실제로 읽힌 후속 신원 비교(_observed_identity_consensus), 마지막 쪽 발급일, 번호 일치 검사를 재사용한다(nhis_acquisition_loss.py:82,:234,:251). 기존 구현이 완전한 쪽 수 검증을 제공한다고 가정하지 않는다. NHIS에서는 1 / N 표시를 수집해 중복·누락·모순 및 실제 쪽 수 불일치를 검토 처리하고, 번호는 각 쪽에서 유효하고 같아야 한다.

추정: 공단의 이어지는 쪽은 신원이나 하단 발급일을 생략할 수 있고 행 번호가 이어질 수 있다. 실제 공단 분쪽 방식은 확인하지 못했다. 합성 다쪽 시험은 이 가정의 방어 동작을 검증할 뿐 실양식 지원을 입증하지 않는다. 후속 쪽의 확인 가능한 신원이 다르거나 번호/쪽 수가 안 맞으면 NEEDS_REVIEW다. 추정과 상충하거나 근거가 부족한 다쪽 입력도 자동 통과시키지 않는다.

### 판정 연결과 최소 수정
- 종류가 슬롯에 맞는 자격득실만 전용 신원 분기를 탄다. 성명·생년월일 모두 있어 본인인증과 일치하면 신원 경고 없음, 하나라도 미판독/불일치면 NEEDS_REVIEW다.
- 납부·자격확인서의 nhis_subscriber_assessment는 그대로 둔다. 자격득실을 이 함수의 가족/가입자 짝 규칙에 추가하지 않는다. doc_check.py의 일반 compare 앞에 자격득실 분기를 두고 필요 시 identity.py에 작은 전용 helper를 둔다. 누락을 건너뛰는 일반 compare나 다른 문서의 FAIL 정책을 바꾸지 않는다.
- _refresh_nhis_identity의 짝 문서 대상 확대는 필요하지 않다. 자격확인서 슬롯 대체 제출은 사용자 정책 결정 전에는 허용 목록에 추가하지 않는다.

### Document AI 밖 원인 후보 처리 선택지
A(권장): 이번 구현은 위 추출·판독검증·최소 판정/변환 연결에 한정한다. 실제 운영 화면 차이는 별도 조사 작업으로 두고 소스 버전·저장 바이트 해시·문서 ID·판독 계층을 값 없이 대조한다.
B: 사용자가 범위를 확장하면 OCR 사슬 일반 예외의 비식별 진단(예외 유형·계층·이유)과 표시 계약 회귀를 별도 단계로 포함한다. 현재 표시 소스는 슬롯명이 아니므로 표시 코드를 선제 수정하지 않는다. 예외 기록에도 본문/필드 원문은 넣지 않는다.
원인이 확인되지 않은 상태에서 expected 강제 분류나 PdfText 날짜 추측을 추가하지 않는다.

## 5) 시험 계획 (명백한 가짜 값)
| 경우 | 수용 기준 |
|---|---|
| 정상 공단 | 성명·생년월일·발급일·발급번호 내부값·각 이력 필드가 기대값과 일치. 올바른 슬롯+일치 신원+업무 조건 충족 시 PASS, 경고 없음. |

## 6) 위험과 사용자가 정해야 할 사항
1. 공고일 당일: 현재는 이상(당일 통과). 유지할지, 정책적으로 초과를 요구하는지 결정 필요. 결정 전 날짜 의미는 바꾸지 않는다.

3. 범위: Document AI + 최소 연결(A) 또는 OCR 사슬/표시 진단까지(B). 동일 파일 화면 문제는 미재현이므로 A 권장, 운영 원인 확정으로 보고하지 않는다.

5. 정부24 공통 helper 변경이 납부확인서 등 다른 추출기에 영향을 줄 수 있다. 기존 동작과 정확히 동등한 함수 분리만 먼저 하고 회귀를 확인한다.
6. 표 레이아웃의 긴 단어가 날짜 토큰과 병합되면 좌표만으로 완전 분리하기 어렵다. 확신 없는 셀을 추측하지 않고 검토 처리한다.
