# 시연 대본 — 신청서류 자동 검토 시스템 데모

시연 시나리오 **10종(S1~S10)**을 순서대로 보여주는 대본이다. 클릭 순서·화면에서
읽을 말·넘어가는 조건을 적었다. 시나리오의 기대 결과는 `demo/fixtures/expected/S*.json`에
기계가 읽는 형태로 따로 있고, 이 대본과 검증 스크립트(`run_p6_scenarios`)가 같은
파일을 본다.

> ⏱ **소요시간 표기 주의.** 아래 분 단위 시간은 **리허설 전 추정치**다. 실측한
> 숫자는 이것 하나뿐이다 — 10종 전체를 서버가 처리하는 데 걸리는 시간은 **약 2초**
> (`run_p6_scenarios` 1회차 기준, 사람 클릭 시간 제외). 나머지는 직접 재 보고
> 이 문서의 숫자를 고쳐 쓰라.

> 🧪 **화면에 뜨는 이름·주소·계좌번호는 전부 가짜다.** 실제 신청자 데이터와 실물
> 서류는 한 건도 쓰지 않는다. 시연 중 이 말을 한 번은 하고 넘어가는 게 좋다.

---

## 0. 시연 전 점검 (5분, 청중 입장 전)

| # | 할 일 | 명령 / 확인 |
|---|---|---|
| 1 | 더미 서류가 있는지 | `demo/fixtures/samples/`에 PDF 25개 (없으면 `python -m demo.fixtures.make_samples`) |
| 2 | 백엔드 중지 후 **리셋** | `python -m demo.backend.reset --yes` |
| 3 | 백엔드 기동 | 저장소 루트에서 `uvicorn demo.backend.main:app --port 8000` |
| 4 | 프론트 기동 | `demo/frontend`에서 `npm run dev` |
| 5 | 열어 두기 | <http://localhost:5173> · 파일 탐색기에서 `demo/fixtures/samples/` |
| 6 | 브라우저 | 개발자도구 **Network 탭**을 미리 열어 둔다 (S9에서 쓴다) |

명령 앞에는 전부 `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`을 붙인다 (Windows 한글 깨짐 방지).

**리셋을 건너뛰지 마라.** 이전 시연의 신청 건이 담당자 목록에 남아 있으면 S9의
"1등 99점"이 달라진다.

## 2. 신청자 화면

### S1 — 자가진단에서 막힌다 (2분 추정)

1. 사업 선택에서 **[전북청년 함께 두배적금]** 클릭
2. 서식2 자가진단 화면 — **원본과 같은 2열 표**(점검내용 | 확인·동의)임을 짚는다
3. 6번 "제외 대상" 문항의 ⑨개 하위 항목을 펼쳐 보인다 (원문 그대로)
4. 6번만 **아니오**, 나머지는 예 → **[자가진단 결과 확인]**

화면에 뜨는 것:

- `6번 문항 — 신청 자격을 충족하지 않습니다.`
- `제외 대상 확인에 동의해야 신청할 수 있습니다.`
- `기초생활수급자 및 법정 차상위계층은 보건복지부 청년내일저축계좌 대상으로, 해당 사업의 혜택이 더 큽니다(3년간 10만원 적립 시 1:3 정부매칭으로 약 1,440만원 수령).`

> **할 말**: "부적격을 알려주고 끝내지 않습니다. 이 분에게 더 유리한 사업이 뭔지
> 같이 알려줍니다. 콜센터 상담 3,073건 중 38%가 자격요건 문의였는데, 안내가 없어서가
> 아니라 **신청자가 스스로 확인할 방법이 없어서** 반복된 겁니다."

넘어가는 조건: 이 건은 임시저장(`DS-2026-000001`) 상태로 남고, 담당자 목록에는

### S2 (1부) — 서식1~5를 수기 0건으로 채운다 (5분 추정) ★ 메인

**[사업 다시 고르기] → [전북청년 함께 두배적금]** 으로 새 신청 건을 연다
(신청번호 `DS-2026-000002`). 자가진단 8문항을 전부 **예**로 통과시킨 뒤 신청서로
넘어간다.

1. **Step0 저축목적·유사사업** — 서식 상단 구획 그대로
2. **Step1 Ⅰ. 기본정보** — 이름 `홍길동`, 생년월일 `1998 / 6 / 15`
   - 날짜가 **년·월·일 3칸**으로 나뉜 것을 짚는다. 브라우저 기본 date 위젯을 쓰면
     서식 칸 안에 이질적인 UI가 들어가 모양이 깨진다.
3. 주소 `전북특별자치도 전주시 완산구 효자동 123`
4. **Step2** — 최종 전입일 `2020 / 11 / 20` 입력
   - ★ **거주기간 체크박스 6칸 중 "5년 이상"이 자동으로 찍히고**, 바로 아래에
     `2020-11-20 전입 → 공고일(2026-03-03)까지 5년 3개월 → 5년 이상` 이 붙는다
   - **할 말**: "서식의 체크박스를 없애지 않았습니다. 모양은 서식 그대로 두고,
     오선택할 여지만 없앴습니다."
5. 가구원 수 `4인`
6. **Step3 근로사항** — 근로유형 `상용직`, 취업일 `2023 / 1 / 2` → 근로기간 자동 체크
7. **Step4** — 계좌 `농협은행 / 302-0000-0000-00 / 홍길동`
8. 상단 **[서식1 전체 보기]** 토글을 켜서 한 장으로 펼쳐 보인다
   - **할 말**: "스텝은 서식을 재구성한 게 아니라 서식의 절(Ⅰ~Ⅳ) 경계를 그대로
     쓴 겁니다. 토글 하나로 원본과 같은 한 장이 됩니다."
9. **동의 단계** — 서식3(수집·이용 + 고유식별정보), 서식4(제3자 제공) 체크
10. **서식5** — 캔버스에 마우스로 서명
    - 옆의 배지를 읽는다: **"현행 지침은 자필서명 — 전자서명 전환 제안"**
    - **할 말**: "여기가 이 데모에서 유일하게 현행 지침과 어긋나는 지점입니다.
      숨기지 않고 화면에 띄워 뒀습니다. 자필 스캔 업로드 모드도 토글로 남겨 뒀고요.
      동의 시각·IP·접속기기가 기록으로 남습니다."
11. **서류 업로드** 화면으로 — 근로유형이 `직장가입자`라 근로확인서류는
    **4대보험 가입내역 확인서** 한 칸만 남는다
    - 근로유형을 지역가입자로 잠깐 바꿔 **목록이 즉시 바뀌는 것**을 보인다 (→ 일용근로내역서)
    - 다시 직장가입자로
    - 화면 상단 "올리기 전에 꼭 확인하세요" 아래의 **(데모 추정치) 각주**를 한 번 짚는다

> **할 말**: "여기까지 종이 0장, 자필서명 0건입니다. 서식1~5 다섯 장을 전부 웹에서
> 썼고, 파일로 올릴 건 **발급받아야만 하는 서류**뿐입니다."

## 3. 담당자 화면

상단 탭에서 **[담당자]** 로 전환.

### S9 — 다운로드 0회 심사 (6분 추정) ★ 메인

1. **역할 토글**을 왼쪽부터 눌러 보인다 — 읍·면·동 / 시군 / 도·청년허브센터
   - 역할마다 **보이는 범위**와 **승인 버튼의 뜻**이 달라진다
     (읍면동 "구비서류 완비 확인" / 시군 "1차 선발 120%" / 도 "최종 선정 100%")
   - **할 말**: "시행지침의 선발절차가 읍면동 → 시군 → 도로 올라갑니다. 같은 화면에서
     역할만 바꿔 그 구조를 보여 드립니다."
2. 역할 **[시군]**, 시군 **전주시** — 목록 3건
3. **정원 배지** — 전주시 550명 / 120% 선발 상한 660명 / 접수 건수
4. 1등(99점, 홍길동) 클릭 → **분할 심사 뷰**
   - 좌 55% 원본 뷰어 / 우 45% AI 판독 결과
   - 서류 탭을 차례로 넘긴다. **다운로드 버튼이 없다**는 것을 짚는다
5. 우측 **서식6 심사표** — 원본 배점표 레이아웃 그대로
   - 항목별 점수 40 / 25 / 25 / 9 = **99점**
   - 각 칸에 근거 문장: `2020-11-20 전입 → 공고일(2026-03-03)까지 5년 3개월 → 5년 이상`
   - 하단 주석: `(데모 추정치) 100% 기준선은 공고문 140% 기준표를 선형 환산한 값입니다.`
6. ★ **"도 거주기간 25점" 칸을 클릭** → 좌측 뷰어가 주민등록초본으로 바뀌고
   **전입일 위치가 하이라이트**된다
   - **할 말**: "'소득분위 초과'라고만 쓰면 담당자는 결국 원본을 뒤집니다.
     근거 문장과 **원본 좌표**를 같이 넘기면 눈으로 3초 안에 검증됩니다."
7. ★ **개발자도구 Network 탭을 보여 준다**
   - 모든 파일 응답의 `Content-Disposition`이 **inline**
   - **attachment 응답 0건**
   - **할 말**: "화면에 버튼이 없는 게 아니라 백엔드에 다운로드 경로 자체가 없습니다.
     소스 전체를 훑어 `attachment`·`download` 문자열이 없다는 것까지 검증 스크립트가
     확인합니다."
8. ★ (선택) 서류 탭 오른쪽 끝의 **[서식1 작성본] · [서식5 작성본]** 탭
   - 신청자가 화면에서 채운 값이 **원본 서식 PDF 위에 그대로 얹혀** 나온다.
     체크박스에 ✓가 찍히고, 서식5 서명란에는 **전자서명이 합성**돼 있다
   - 이것도 내려받지 않는다 — 같은 뷰어, 같은 `inline`
   - **할 말**: "종이로 받던 서식이 그대로 나옵니다. 담당자 입장에서 달라지는 건
     글씨를 알아볼 수 있다는 것과, 빈칸이 없다는 것뿐입니다."
   - 준비가 안 된 환경(원본 시행지침 PDF 없음)에서는 이 탭이 **아예 뜨지 않는다.**
     대본에서 통째로 건너뛰어도 나머지 시연에 영향이 없다

## 4. 사업을 바꿔 본다

### S10 — 취업지원패키지 (5분 추정)

신청자 화면으로 돌아가 **[사업 다시 고르기]** → **[전북청년 취업지원패키지]**
(신청번호가 `DS-`가 아니라 `JP-2026-000005`로 바뀌는 것도 한 번 짚는다).

1. **자가진단이 8문항에서 2문항으로 줄어든다** (나이·거주지)
   - **할 말**: "화면에 사업 코드 분기가 한 줄도 없습니다. 문항 수도, 서식도, 동의
     항목도 전부 서버의 사업 설정에서 나옵니다."
2. 신청서 작성 (`최청년`, 계좌) — 거주기간·근로사항·가구소득 칸이 아예 없다
3. **지원 항목 선택** — 면접비 **2회**, 정장비 **1회** (영수증 `70,000`원),
   자격증 응시료 **1회** (영수증 `43,000`원)
   - 예상 지원금이 실시간으로 **193,000원**
   - ★ 정장비 줄의 계산 근거: `영수증 70,000원 > 한도 50,000원 → 50,000원 지급`
   - **할 말**: "면접비만 정액 5만원이고 영수증이 필요 없습니다 — 면접확인서만
     내면 됩니다. 나머지 3종은 실비라 영수증 금액과 한도 중 작은 값입니다."
4. 면접비 횟수를 **3회**로 올려 본다 → 2회로 깎이고 "최대 2회" 경고가 뜬다
5. **서류 체크리스트가 7칸으로 조립된 것**을 보인다 (초본 + 면접확인서 2 + 정장 2 + 자격증 2)
   - 사진비만 남기면 3칸으로 줄어든다 (한 번 보여 주고 되돌린다)
6. 자격증 슬롯에 `S10_응시확인서_응시일없음.pdf` → **부적합**
   - "'응시확인서 또는 성적표'에서 응시일을 찾지 못했습니다."
   - **할 말**: "사업계획서가 '(응시일 표기 필수)'라고 못 박은 항목입니다."
7. `S10_응시확인서_적합.pdf`로 교체 → 적합. 나머지 서류를 올린다
8. **제출** → `접수 순번 1번 / 총 지원규모 900건`, `서류 미비 시 7일 내 보완 안내`
9. 담당자 화면으로 전환 → 사업 필터를 **취업지원패키지**로
   - **접수순** 정렬 (두배적금은 점수순), 총량 900건 진행률 배지
   - 항목별 지급 내역 193,000원

> **할 말 (마무리)**: "같은 엔진, 같은 화면입니다. 사업 설정만 바꿨더니 연령 기준일,
> 서류 인정일, 소득요건 유무, 선발 방식, 보완 정책, 담당자 목록의 정렬까지 전부
> 따라 바뀌었습니다."

## 6. 사고 대응

| 증상 | 대응 |
|---|---|
| 업로드했는데 판정이 이상하다 | 파일명이 바뀌면 Tier1 고정 결과를 못 찾고 Tier2(실제 판독)로 넘어간다. `fixtures/samples/`의 **원래 파일명 그대로** 쓴다 |
| 담당자 목록에 모르는 건이 있다 | 리셋을 안 했다. 시연을 멈추고 `reset --yes` 후 백엔드 재기동 |
| 리셋이 실패한다 | uvicorn을 먼저 멈춘다 (Windows는 실행 중인 SQLite 파일을 못 지운다) |
| 한글이 깨진다 | `PYTHONIOENCODING=utf-8 PYTHONUTF8=1`을 명령 앞에 붙였는지 확인 |
| 화면이 좁아 서식이 잘린다 | PC 전용이다. 가로 스크롤로 보거나 브라우저 폭을 넓힌다 (1280px 이상 권장) |
| 질문: "실제 OCR인가?" | 시연 파일은 고정 결과를 쓰지만, **아무 정부24 PDF나 올려도** Tier2가 텍스트 레이어에서 문서종류·발급일·가구원수·건보료를 실제로 읽는다. 그 자리에서 임의 PDF를 올려 보여 줄 수 있다 |
| 질문: "점수가 맞나?" | 시행지침 서식6 배점표와 숫자까지 대조했고, 수기 검산(40+25+25+9=99)과 일치하는지를 검증 스크립트가 매번 확인한다 |
