# 기획·계획서

## 배경과 목표

함께 두배적금은 정원 1,300명에 12,821건이 접수되어 신청자 한 명당 7\~8개 서류를 수기로 검토해야 했습니다. 이를 적용하면 전체 서류는 약 10만 건에 이릅니다. 전주시 기준 심사에는 1\~2개월이 걸렸고, 콜센터에는 자격요건과 제출서류 관련 문의가 반복됐습니다. 2026년 콜센터 상담 3,073건 가운데 38%는 자격요건, 14%는 제출서류 문의였습니다. 2027년 운영계획은 담당자 중심 확인·안내를 시스템 기반 자동 확인·분류·알림으로 바꾸는 방향을 제시합니다.

현재 데모는 함께 두배적금과 청년 취업지원패키지 신청자마다 제출하는 여러 서류의 종류, 발급 시점, 자격과 기준 충족 여부를 확인하는 흐름을 구현합니다. 업로드 때 미비 가능성을 안내하고 자동 판정 근거와 확인할 원본을 담당자 화면에 모읍니다. 목표는 서류 확인에 드는 반복 작업을 줄이고 신청자가 제출 오류를 일찍 알도록 돕는 것입니다. 최종 자격과 점수 기준은 공고문과 기관이 정한 규칙을 따릅니다.

## 수요기관 요구와 기능 대응

요구 항목은 함께 두배적금·청년 취업지원패키지 문제 제안서의 요구를 기준으로 정리했습니다.

| 수요기관 요구 | 시스템 대응 | 상태 |
|---|---|---|
| 서류 자동 분류 | 본문을 바탕으로 필요한 서류 종류인지 확인하는 기존 판정 흐름이 있습니다. 별도 학습형 분류 모델은 실험 중이며 데모 판정에는 연결되지 않았습니다. | 기존 규칙 흐름 구현, 모델 연결 진행 중 |
| 학습형 OCR | OCR(서류 사진이나 PDF에서 글자를 읽는 기술)인 own은 공개 사전학습 PP-OCRv5 mobile 모델을 기관 내부 CPU(컴퓨터의 중앙 처리 장치)에서 실행합니다. own 학습 단계와 데모 기본 엔진 연결은 진행 중입니다. | 엔진 구현, 데모 연결·학습 진행 중 |
| 서식에 맞춘 핵심값(KV) 추출 | 서류 종류별 추출기가 이름·날짜·금액 등 필요한 항목을 다룹니다. KV(항목 이름과 그에 해당하는 값) 추출의 서식 변화와 발급일 선택, 표 행 정렬 등 규칙을 보강하고 있습니다. | 일부 구현, 보강 진행 중 |
| LLM/NLP 정보 추출 | LLM(대규모 언어 모델)과 NLP(자연어 처리)는 글의 맥락과 정보를 다루는 기술입니다. 텍스트와 위치를 이용해 필요한 정보를 읽습니다. 현재 데모의 주 경로는 OCR·문서별 추출기입니다. LLM/NLP 기반 외부 정보 추출의 전면 도입은 완료된 기능으로 보지 않습니다. | 제한된 추출 흐름 구현, 확대 검토 |
| 규칙 기반 자격·점수 판정 | 사업별 기준 설정과 기존 엔진 규칙으로 공고문 항목을 판정합니다. 두배적금 근로 요건 판정 등 일부 항목은 진행 중입니다. | 일부 구현, 항목별 진행 중 |
| 신뢰도 점수에 따른 담당자 확인 | 판독 신뢰도가 기준에 못 미치거나 판별할 수 없는 경우 확인필요로 넘깁니다. 설정된 신뢰도 기준은 데모 가정값을 포함합니다. | 데모 흐름 구현 |
| 보완 요청 문구 | 사업별 제출·보완 안내를 화면에 표시합니다. 취업지원패키지 데모는 보완 기한을 7일로 설정하고, 두배적금은 보완 요청 없이 미비 시 선발 제외하는 흐름입니다. | 데모 구현, 실제 기관 문구 확정 필요 |

## 설계 방식

인식 모델은 서류의 글자와 항목을 읽는 데 사용합니다. 자격 판정과 점수 계산은 공고문 기준을 그대로 옮긴 규칙이 담당하며, 머신러닝(ML, 데이터를 학습해 예측하는 방식)으로 점수를 매기지 않습니다. 규칙과 기준을 확인할 수 있도록 판정 근거를 남깁니다.

판독이 불확실하거나 필수 정보를 읽지 못하면 자동으로 부적합을 확정하지 않고 담당자가 확인합니다. 신청자 화면에는 제출 안내와 신청에 필요한 결과만 보이고, 내부 점수·배점·판정 단서는 표시하지 않습니다. 담당자는 원본과 판독 결과를 함께 확인합니다.

개인정보가 포함된 서류는 기관 내부 엔진 처리를 우선합니다. 외부 전송은 기관이 확인한 범위 안에서만 허용하도록 설계합니다. 전북AI OCR 경로에서도 주민등록번호 뒷자리는 응답을 받은 즉시 지우고 원문을 보관하지 않습니다.

## 현재 상태

### 구현 완료

- 함께 두배적금과 청년 취업지원패키지 두 사업의 신청·서류 검토 데모가 있습니다.
- 업로드한 서류의 종류·발급일·필수 항목을 확인하고 제출 시 공고문 기준 자격 요건을 검사합니다.
- 다른 종류의 서류를 올린 경우 안내하고, 부모 명의 건강보험 서류의 확인과 신청자 화면의 타인 이름 비노출을 처리합니다.
- 가구원 수는 건강보험 자격확인서만 근거로 사용합니다.
- 담당자 화면에서 판정 근거와 원본 서류를 함께 봅니다. 사업별 기준은 버전으로 관리하며 신청 건은 생성 당시 버전을 유지합니다.
- own OCR은 공개 사전학습 PP-OCRv5 mobile(문자 영역 탐지·한국어 글자 인식) 모델을 ONNX(서로 다른 실행 도구가 사용할 수 있는 모델 파일 형식)로 변환해 ONNX Runtime(ONNX 모델 실행 도구)으로 내부 CPU에서 실행합니다. 입력은 외부로 보내지 않으며 결과에 글자 위치와 신뢰도를 포함합니다. 원본 모델은 Apache-2.0입니다. 모델은 검증된 내려받기 스크립트로 설치하며 저장소에 포함하지 않습니다.
- own의 제한된 실서류 시험은 주민등록초본과 4대보험 가입내역에 한정했습니다. 해당 문서 범위에서 로컬 OCR(Apple Vision)과 비슷한 수준으로 필드를 읽었고 발급일 등 일부 추출 규칙은 보완 중입니다. 이 관찰은 시험한 문서에만 해당하며 수치 성능이나 일반 문서 성능을 뜻하지 않습니다.
- 신청 서식은 원본 PDF 위에서 온라인 작성·서명합니다. 작성한 서식은 PDF 한 파일과 원본 HWP로 받을 수 있으며, 두배적금 서식5는 스캔 제출도 선택할 수 있습니다.

### 진행 중

- own을 신청자 화면 판독 체인의 기본 엔진으로 연결하고 인식 모델을 미세 조정하며 담당자 수정 결과를 반영해 다시 학습하는 단계를 마련합니다.
- 문자 변형, 발급일 선택, 표 행 정렬 등 추출 규칙을 보강합니다.
- 서류 종류 판별을 보강하고 실험 중인 분류 모델을 연결할지 검토합니다. 현재 분류 모델은 데모 판정에 연결되어 있지 않습니다.
- 담당자 화면에서 원본의 판독 위치를 강조합니다. 전북AI 결과에는 원본 좌표가 없어 해당 결과만으로는 강조할 수 없습니다.
- 두배적금 자격요건 기준화(I)와 근로 판정(J)을 진행합니다.

### 제안

알림톡 연동은 제안 단계입니다. 완료된 기능이나 확정된 일정으로 안내하지 않습니다.

| 위험 | 대응 |
